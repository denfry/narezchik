# subtitle-director

Решает, КАК текст появляется на экране — редакторская часть; механический рендер в .ass
делает `scripts/pipeline/generate_subtitles.py` (см. [[ffmpeg-editor]]) строго по тому, что
здесь решено. Этот skill не пишет .ass напрямую — он заполняет `subtitle_events` в edit plan.

## Когда использовать

После [[visual-director]] зафиксировал `visual_events` (субтитры должны не спорить с уже
решённым визуальным акцентом на тот же момент), перед рендером.

## Черновик — скриптом

`python scripts/pipeline/build_subtitles.py edit-plans/<plan>.json` (режим `word` для
вертикали, `chunk` для горизонтали) сам раскладывает слова по сегментам и пересчитывает
тайминги в шкалу готового ролика. Вручную слова НЕ выписывать: это сотни событий и главный
источник рассинхрона. Твоя работа — `emphasis` и плашки `hook_headline`/`emphasis_callout`/
`speaker_label` поверх результата. Если в `channel/profile.md` задан другой стиль субтитров —
он главнее описанного ниже.

## Формат — пословный, а не чанками (по умолчанию для вертикали)

Основной режим — **пословные субтитры**: заполняется `subtitle_events[].words` —
массив `{word, start_sec, end_sec, emphasis}` со всеми словами сегмента. На экране всегда
видно одно слово — то, которое звучит прямо сейчас (окно из 3 слов читалось хуже), акцентное окрашено цветом акцента бренда,
соседние белые. Одно событие `Dialogue` на слово генерируется автоматически.

Слова берутся из `transcripts/<clip_id>.json` (`segments[].words[]`) — те, что попадают
в интервал `speech_edits`, с пересчётом в кумулятивное время готового ролика: вычесть
`source_start_sec` сегмента, прибавить сумму длительностей предыдущих сегментов. Тайминги
не выставлять на глаз: рассинхрон на пословном режиме заметен мгновенно.

Обычно одно `subtitle_events`-событие на один `speech_edits`-сегмент. Поле `text` при этом
заполняется целиком по сегменту и служит только для чтения человеком — на экран идут `words`.

Старый режим (`text` без `words`) остаётся рабочим для одиночных плашек: `hook_headline`,
`emphasis_callout`, `speaker_label`. Для обычной речи его не использовать.

Шрифт — Montserrat ExtraBold из `assets/fonts/` (подключается через `fontsdir`, в систему
ставить не нужно), кегль 96, нижний отступ 420 px: интерфейс Shorts занимает примерно
нижние 320 px, остальное запас. Отступы не переопределять без причины.

## Требования к читаемости

- **Mobile-first, максимум 1-2 коротких строки** одновременно на экране — не абзацы.
- **Смысловое разделение**, не механическое "по N слов". Разбивать на естественных паузах/
  границах мысли — фраза не должна обрываться посередине смыслового блока, если этого можно
  избежать без ломки синхронизации с речью.
- **Синхронизация с речью** — `start_sec`/`end_sec` каждого чанка берутся из word-level
  таймкодов `transcripts/<clip_id>.json` (через `words[].start/end` для первого и последнего
  слова чанка), не "на глаз".
- **Safe margins** — не заезжать за края безопасной зоны кадра (уже заложено в ASS-стилях
  `generate_subtitles.py`: `MarginL/MarginR = 40`, `MarginV` подобран так, чтобы не залезать
  на UI Shorts/Reels снизу/сверху — не переопределять эти отступы без причины).
- **Не закрывать лицо** — если крупный план в этот момент занимает центр-низ кадра
  (см. `crop`/`zoom` из соответствующего `visual_events`), учитывать это при выборе
  `style`/эффективного вертикального расположения; для этого канала базовая позиция —
  нижняя треть кадра, поднимать выше только если сцена/b-roll в кадре внизу.
- **Нормальная кириллица** — никаких транслитераций/латиницы вместо русских букв, точные
  ё/й на месте (не срезать до "просто е"), если так было в оригинальной речи.

## Смысловое выделение (emphasis)

В пословном режиме акцент — это `emphasis: true` на слове: оно получает scale-pop, короткий
рывок масштаба в момент произнесения. Ставить **не чаще одного акцента на 5-6 слов**. Это
жёсткое ограничение, а не пожелание: подсветка работает только как контраст, и если
подсвечено каждое третье слово, она перестаёт значить что-либо вообще.

Выделять: цифры и проценты, ключевое слово punchline'а, существительное, ради которого
произносится фраза, слово с основным emotional beat. **Повторы не подсвечивать** — если
слово уже подсвечивалось в этом ролике (в перечислениях вроде «пусть у тебя будут… пусть
у тебя будут…»), второй акцент только размывает первый.

Поле `emphasized_words` на событии дублирует список для читаемости плана человеком;
источник истины — флаг `emphasis` внутри `words[]`.

## Стили события (`style` в schema)

- `caption` — базовые субтитры реплики;
- `hook_headline` — крупный заголовок поверх HOOK (первые ~1.5-2.5с ролика), отдельно от
  обычных caption-чанков, не заменяет их — обычно идёт ПОВЕРХ или ПЕРЕД первым caption;
- `speaker_label` — короткая подпись имени говорящего при смене реплики (подкасты с
  двумя спикерами; имена — `speaker_names` в `channel/brand.json`);
- `emphasis_callout` — отдельный крупный текстовый акцент, соответствующий
  `visual_events` типа `text_emphasis`/`graphic` (см. [[visual-director]]) — при таком
  visual event ОБЯЗАТЕЛЬНО должен быть соответствующий `subtitle_events` с этим стилем,
  иначе рендер (`render_short.py`) не отрисует текст для этого события, он не рисует его
  сам по себе, только через subtitle-слой.

## Процесс

1. Для каждого `speech_edits` сегмента взять `words[]` из транскрипта в диапазоне сегмента
   и пересчитать тайминги в кумулятивное время ролика.
2. Записать их в `subtitle_events[].words` — одно событие на сегмент. Группировать в чанки
   вручную не нужно: пословный вывод формируется при генерации .ass (`build_word_events`, max_words=1).
3. Расставить `emphasis` по правилу выше — не чаще одного на 5-6 слов.
4. Один `hook_headline` chunk на самое начало ролика, с текстом-крюком (можно опираться на
   `clip.hook` из viral-moment-finder, но переформулировать под то, что реально влезет в
   1-2 строки крупным шрифтом).
5. Если есть спикерские переключения (интервью/подкаст) — `speaker_label` chunks на каждой
   смене говорящего.

## Проверка перед сдачей

- Нет наложения двух `caption` событий друг на друга по времени.
- Акцентов не больше, чем одно слово на пять — посчитать, а не прикинуть.
- Последнее слово ролика попадает в разметку: обрыв субтитров за секунду до конца читается
  как технический сбой.
- Прогнать `python scripts/pipeline/generate_subtitles.py edit-plans/<clip_id>.json` — если
  падает на конкретном событии, значит в данных ошибка (не в скрипте — он чисто механический).

## Выход

`subtitle_events[]` в edit plan, `project.stage = "subtitles_planned"`. Дальше —
[[sound-designer]] и финально [[ffmpeg-editor]].

## Если это лонг, а не Shorts

Пословные субтитры кеглем 128 — язык вертикального фида без звука. В горизонтальном лонге
`generate_subtitles.py` сам переключается на фразовый режим (`chunk`, кегль 54, нижняя
треть) по формату из `render_settings`. Твоя часть от этого не меняется — те же
`subtitle_events` с `words` и точечным выделением; менять `subtitle_mode` руками только
если пользователь явно просит другое. Почему так — `docs/playbook.md`, раздел про субтитры.
