# long-form-structure

Редакторский шаг лонг-пайплайна: из часа исходника собрать 5-15 минут, которые держатся
как цельный ролик, а не как склейка сильных цитат.

## Когда использовать

После [[transcription]], когда цель — длинный ролик. Триггеры: «смонтируй лонг»,
«собери ролик по сценарию», «сделай длинное видео из этого подкаста».
Для Shorts этот skill не нужен — там работают [[viral-moment-finder]] и
[[shorts-script-editor]].

Если под ролик уже есть сценарий (`ideas/<clip_id>_long*.md` от скаута или файл пользователя) — он и есть источник структуры.
Не переизобретать её: в сценарии уже приняты решения по хуку, порядку блоков и CTA,
задача skill'а — перевести их в `speech_edits[]` с точными таймкодами по word-level
транскрипту. Расходиться со сценарием можно, но каждое расхождение записывать в
`project.notes` с причиной.

## Разница с шортсом, которую нельзя игнорировать

У шортса зритель решает за 1-3 секунды, у лонга — дважды: на 15-й секунде (остаться ли)
и на 2-3 минуте (досматривать ли). Поэтому:

- **Хук (первые 15-30 с)** делает две вещи сразу: цепляет И обещает структуру («разберу
  три причины, третья неочевидная»). Один только цепляющий тезис без обещания даёт отвал
  на второй минуте.
- **Первая фраза — самая острая реплика материала, без подводки.** Если сильнейшая
  реплика звучит на 18-й секунде исходного порядка — поставить её первой. Обещание —
  плашкой поверх речи, а не отдельным немым кадром. В споре к 0:30 зритель должен
  услышать первый ответ, а не только заявку на спор. Основная потеря зрителей — в первые
  40 секунд; ориентир — 80 % зрителей на 0:30.
- **Нумерованный формат держит середину.** Ролик собирается вокруг числа: N вопросов,
  N противоречий, N раундов, обратный отсчёт. Счёт даёт причину досмотреть до первого
  места. Самый сильный пункт — последним, и сказать об этом в начале. Номер пункта висит
  на экране весь пункт (`make_cards.py rankplate`), чтобы пришедший с середины понимал,
  где он.
- **Длина 7–9 минут по умолчанию.** Короткий лонг держит больший процент и быстрее
  подхватывается рекомендациями; длиннее — только если материал тянет нумерованный формат.
- **Обещание обязано выполниться.** Пообещал три причины — в ролике должны быть три
  причины, явно отбитые. Невыполненное обещание бьёт по каналу сильнее, чем слабый хук.
- **3-6 смысловых блоков (глав)**, у каждого своя функция: диагноз, механика, история/
  кейс, практика, возражение и ответ, вывод. Блок без функции — кандидат на вырезание,
  даже если внутри хорошая речь.
- **Каждые 60-90 секунд — повод остаться**: новая мысль, история, цифра, смена крупности.
  Провал между поводами — это то место, где падает график удержания.
- **Бэкстори работает как доверие, а не как биография.** Ставить его после того, как
  зритель уже понял, зачем ему слушать — не в самое начало.
- **Не резать смысловые паузы спикера** (см. `channel/profile.md`) — на длинной дистанции
  они и есть темп; вычищаются только технические заминки и повторы. Черновик —
  `auto_cut.py --max-pause 0.9` по каждой главе, дальше редактура.
- **Транскрипт целиком не перечитывать:** оглавление — `transcript_window.py <id> --outline 60`,
  текст глав — `transcript_window.py <id> --from S --to E`.

## Что записать в edit plan

- `speech_edits[]` — сегменты в порядке монтажа, каждый с `role`. Для лонга роли шире
  шортсовых: `hook`, `promise`, `backstory`, `chapter`, `story`, `objection`, `practice`,
  `cta`, `payoff`. Границы — строго по word-level таймингам из `transcripts/<clip_id>.json`,
  ни один рез не внутри слова.
- `project.notes` — почему выбрана такая структура, что выброшено и почему. Это то, к чему
  возвращается перемонтаж: без записанной причины следующая итерация выбросит то же самое
  заново или вернёт вырезанное.
- Главы — в `project.notes` списком «MM:SS — название» от начала готового ролика (сумма
  длительностей предыдущих сегментов). Оттуда они переносятся в описание на YouTube.
- `render_settings`: `width: 1920`, `height: 1080`, `inherit_source_resolution: true`
  (из 4K-исходника лонг уходит в 3840×2160 — YouTube тогда кодирует VP9, а не мыльный AVC),
  `crf: 16`, `preset: "slow"` (или `medium`, если 4K и время поджимает), `color_grade`
  выбран под настроение ролика (`cinematic_warm` — разговор/дебаты, `cinematic_cool` —
  деньги/дисциплина, `punchy` — провокация), `cover_frame.enabled: false`
  (у лонга превью грузится в Studio отдельным файлом, вклеивать кадр не нужно).
- `project.stage = "script_edited"`.
- **Титр главы на каждом блоке** (visual_events `type: "graphic"` или `text_emphasis`
  на первых 2–3 с блока, текст = название главы из `project.notes`). Это «чекпоинт» для
  зрителя и один из визуальных ивентов, которые не дают retention-editor поднять флаг
  «75 с без события». Главы длиной 3–5 минут, не больше.
- **Сегмент-зазывалка** (`role: "cta"`, `source_path` на файл из `cta/`, 8–15 с) —
  только если в `channel/profile.md` включена CTA-зазывалка со своим звуком. Закладывается
  уже здесь отдельным элементом `speech_edits` в первом смысловом шве после первой
  ценности — детали в skill cta-director. Его длительность учитывается в таймкодах глав.
- `render_settings`: `lut` (один из `assets/luts/*.cube`, чередовать между роликами),
  `lut_strength` 0.5–0.7, `film_grain` 0.2–0.3; `tail_card.image_path` — горизонтальная
  плашка из `cta/` (или `make_cards.py tail`), если она есть.

## Проверки перед передачей дальше

- Суммарная длительность `speech_edits` попадает в 5-15 минут (цель — 7–9, если профиль
  канала не говорит иначе). Если вышло 20+ — это не
  «длинный ролик», это неразобранный исходник: вернуться и выбросить блок целиком, а не
  подрезать по секунде везде.
- Обещание из хука закрыто явно, а не «подразумевается».
- Ни один сегмент не начинается с середины мысли («...и поэтому он ушёл») — зритель
  не слышал первой половины.
- Контент-правила — `channel/content-rules.md`: «стоп»-категории не берутся, новая
  категория риска = файл `⚠️ТРЕБУЕТ_РЕШЕНИЯ.md` и вопрос пользователю.

Дальше по пайплайну — [[retention-editor]] (он же работает и для лонга; ищет провалы
между поводами остаться), затем [[visual-director]], [[subtitle-director]],
[[sound-designer]], [[ffmpeg-editor]].
