# broll-researcher

Находит (или готовит поисковый запрос на) конкретные внешние медиа-файлы под уже принятые
visual-director решения "здесь нужен broll". Не решает, где вставлять b-roll — это уже
решено на предыдущем шаге; здесь решается ЧЕМ именно заполнить это место.

## Когда использовать

После [[visual-director]] оставил в `visual_events` события типа `broll`/`screenshot`/
`image_insert` со ссылкой `asset_ref` на ещё не существующий asset (или вообще без
`asset_ref` — тогда сначала завести запись в `assets[]`).

## Что делать

1. Для каждого такого события прочитать `description`/`purpose` и соответствующий кусок
   `transcript_text` из `speech_edits` (через `segment_ref`) — понять, что именно там
   называется/подразумевается.
2. Решить, ДЕЙСТВИТЕЛЬНО ли здесь нужен внешний асфет, или планка "иллюстрирует то, о чём
   говорят / даёт доказательство / объясняет сложную мысль / добавляет контекст / повышает
   visual variety" не набирается — если ни один из этих пяти критериев не выполняется
   уверенно, вернуть событие visual-director с пометкой "заменить на punch-in/text_emphasis,
   b-roll здесь не оправдан" вместо того, чтобы тянуть слабый asset только чтобы что-то было.
3. Если b-roll оправдан — заполнить в `assets[]`:
   - `id` (совпадает с `asset_ref` события);
   - `kind` (`broll_video` / `image` / `music` — здесь обычно первые два);
   - `path`, ЕСЛИ подходящий файл уже есть в `assets/broll/` (проверить сначала — не плодить
     дубликаты одного и того же материала под разными именами);
   - иначе `search_query` — конкретный, специфичный запрос (не "деньги", а "пачка долларов
     крупным планом на столе" / не "город", а "ночной Дубай skyline драйв").
4. Пользователь может генерировать/подбирать сам этот asset (AI-генерация изображений,
   стоковое видео) — задача этого skill дать ему точный, применимый запрос, не пытаться
   самостоятельно скачивать сток из интернета без явного запроса пользователя на это.
5. Когда пользователь предоставил файл — положить его в `assets/broll/` (видео) или рядом
   по смыслу, обновить `assets[].path`. Никогда не удалять/перезаписывать assets, на
   которые уже ссылаются другие edit plan'ы.

## Если asset так и не появился

Пайплайн обязан уметь продолжить работу без b-roll. `scripts/pipeline/render_short.py` уже
устроен так: если `asset_ref` есть, а файла на диске нет — событие тихо пропускается с
предупреждением в лог, рендер идёт дальше на обычном talking-head плане из visual-director
(там всегда должен быть валидный crop как fallback, см. [[visual-director]]). Явно
сообщить пользователю, какие b-roll места остались незакрытыми, если это существенно
влияет на понятность ролика.

## Выход

Заполненные/размеченные `assets[]`. `project.stage` не меняется этим шагом сам по себе —
он часть общей стадии `visual_planned`/`broll_planned`, отмечать `broll_planned`, когда все
broll-события в плане либо получили asset, либо осознанно оставлены как "b-roll не
оправдан, событие удалено/заменено".


## Лимит вставок: четыре на минуту речи

Из практики нарезчиков: на минутный ролик четыре вставки — «больше чем достаточно»,
дальше — «главное не борщить».

Правило для наших планов: **не больше четырёх врезок на минуту речи**, каждая 2–3
секунды. Врезка ставится только там, где сказанное можно показать буквально: названа
вещь, цифра, место, действие. Иллюстрация к абстракции («отношения», «ценность»,
«уважение») не ставится вовсе — она не добавляет смысла и сбивает темп.

Считать лимит по всему ролику, а не по эпизоду: лонг на восемь минут — это не тридцать
две врезки подряд, а максимум столько при условии, что каждая оправдана отдельно.
Партнёрская врезка (`insert_purpose: "cta"`) в этот лимит не входит.
