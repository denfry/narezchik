# ffmpeg-editor

Чистый исполнитель. Все смысловые решения к этому шагу уже приняты предыдущими skills и
записаны в `edit-plans/<clip_id>.json` — этот skill их читает и превращает в реальный файл
в `output/`. Если чего-то не хватает в плане (нет speech_edits, битые ссылки) — это повод
вернуться на предыдущий шаг, а не додумывать недостающее здесь.

## Когда использовать

Когда `edit-plans/<clip_id>.json` прошёл [[sound-designer]] (или хотя бы
[[subtitle-director]], если звук решили оставить дефолтным — `audio_events` пустой массив
валиден) и готов к сборке.

## Процесс

1. **Всегда сначала валидировать**: `python scripts/pipeline/validate_edit_plan.py
   edit-plans/<clip_id>.json`. Не рендерить план с ошибками валидации.
2. Рендер: `python scripts/pipeline/render_short.py edit-plans/<clip_id>.json`
   (на своём сервере — `python scripts/remote/remote.py render edit-plans/<clip_id>.json`;
   пока пользователь работает за ПК — с `SHORTS_LOW_PRIORITY=idle SHORTS_THREADS=4`) (добавить
   `--use-gpu`, если нужен быстрый h264_nvenc проход вместо libx264 — но по умолчанию не
   форсировать GPU-энкодер без причины, libx264 стабильнее по качеству при том же битрейте).
3. Скрипт сам делает по порядку: режет и кропит каждый `speech_edits` сегмент под
   `render_settings.width/height` (default 1080x1920) с учётом crop/zoom/freeze_frame из
   `visual_events`; склеивает через concat demuxer **с реэнкодом** (см. ниже про известный
   баг); best-effort оверлеит `broll`/`screenshot`/`image_insert`, пропуская события без
   asset-файла на диске; сводит звук по `audio_events` (music bed + сайдчейн-дакинг, если
   есть) и всегда финиширует `loudnorm` к `render_settings.target_lufs`; прожигает
   `subtitle_events` через `scripts/pipeline/generate_subtitles.py`, если они заданы.
4. Результат — `output/<clip_id>.mp4`. Скрипт сам обновляет `edit_plan.output_path` и
   `project.stage = "rendered"`.
5. Скрипт печатает `expected ~Ns, actual Ms` и предупреждение, если фактическая
   длительность результата заметно (>5% или >1с) отличается от суммы длительностей
   `speech_edits`. **Если видишь это предупреждение — не игнорировать.** Известный баг:
   склейка сегментов через `-c copy` не гарантированно совместима по параметрам кодека
   между независимо нарезанными кусками, из-за чего concat молча брал только первый
   сегмент — текущая версия всегда реэнкодит на склейке именно поэтому. Если предупреждение
   всё равно всплыло — проверить, не поменялся ли скрипт обратно на stream-copy, это
   регрессия того же бага, чинить тем же способом (реэнкод на concat, не stream-copy).

## Технический стандарт по умолчанию

`libx264`, CRF 16 / preset `slow`, profile High, GOP 2 с (или `h264_nvenc` с
`--use-gpu`), `AAC` 192k. Shorts — `1080x1920`; лонг из 4K-исходника — `3840x2160` через
`inherit_source_resolution: true`. Дефолты зашиты в схеме и `render_short.encoder_args`,
менять только по явной причине. После рендера обязательно ffprobe выхода: битрейт 4K-лонга
не ниже ~20 Мбит/с, 1080p — не ниже 8, иначе YouTube отдаст мыло (см. docs/render.md).

## Что делать при ошибке рендера

Скрипт останавливается на первой же непрошедшей ffmpeg-команде и печатает хвост stderr.
Частые причины:
- путь к исходнику в `source.path` не существует (файл удалили/переместили из `input/`);
- `speech_edits` таймкоды выходят за пределы `source.duration_sec` (должно было отловиться
  на validate_edit_plan.py — если долетело сюда, значит план не валидировался перед
  рендером);
- asset для overlay указан с `path`, но файл битый/не тот формат — не мешает рендеру
  видео-части (broll-события без валидного файла пропускаются), но при явном `path`,
  который есть на диске, но ffmpeg не может его декодировать, упадёт вся overlay-стадия —
  сообщить пользователю, какой именно asset проблемный.

## Никогда

- Не изменять исходники в `input/` — только читать.
- Не редактировать `edit-plans/*.json` руками параллельно с рендером — редакторские
  решения принимаются на предыдущих стадиях, этот skill только выполняет.
- Не пытаться "починить" плохой монтаж внутри ffmpeg-editor (перекроить тайминги,
  добавить эффект от себя) — вернуть план на нужную предыдущую стадию.

## Выход

`output/<clip_id>.mp4`, `edit_plan.output_path` и `stage = "rendered"`. Дальше —
[[shorts-qc]].
