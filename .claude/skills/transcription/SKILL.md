# transcription

Формирует единственный источник правды о том, что и когда было сказано. Все последующие
стадии (viral-moment-finder, shorts-script-editor, subtitle-director) работают с
таймкодами и текстом из этого транскрипта, а не пересматривают видео заново.

## Когда использовать

Сразу после [[video-ingest]], если `transcripts/<clip_id>.json` ещё не существует. Если
файл уже есть — не перегонять заново (транскрипция дорогая по времени), переиспользовать.
Также по прямой просьбе пользователя перетранскрибировать (напр. если распознавание
оказалось плохим и нужна модель покрупнее).

## Что делать

1. Запустить `python scripts/pipeline/transcribe.py input/<файл> --clip-id <clip_id>`.
   По умолчанию модель `medium`, `device=auto` (пробует CUDA через ctranslate2 — она
   работает независимо от того, CPU или GPU сборка torch, см. docs/setup.md — и падает
   обратно на CPU int8, если CUDA недоступна или модель не помещается в VRAM). Без
   NVIDIA брать `--model small --device cpu`: medium на CPU для часового файла — часы.
   Если настроен свой сервер (docs/remote.md) — `python scripts/remote/remote.py transcribe ...`.
2. Для длинных исходников (подкасты 2+ часа) можно взять модель `small` для скорости
   первого прохода, а на финальную версию выбранных фрагментов — перетранскрибировать
   узкий отрезок моделью `medium`/`large-v3` для точности (см. `--model`).
3. Результат — `transcripts/<clip_id>.json`: список `segments[]`, у каждого `start`, `end`,
   `text` и `words[]` (`start`, `end`, `word`). И параллельно `transcripts/<clip_id>.txt` —
   компактный `[start-end] text` формат, для быстрого чтения глазами.
4. **Проверка контент-правил — дело скаута ([[viral-moment-finder]]), не этого шага.**
   Транскрипт не перечитывать целиком ради проверки: это самый дорогой по токенам файл
   проекта. Скаут читает его один раз и сверяет с `channel/content-rules.md`.
5. **Вычитка.** ASR ошибается в именах, терминах, числах, а субтитры берутся прямо из
   транскрипта. Для фрагментов, которые пойдут в ролик:
   `python scripts/pipeline/proofread_transcript.py dump transcripts/<clip_id>.json` →
   выписать правки → `... apply transcripts/<clip_id>.json temp/<clip_id>_fixes.json`.
   Словарь имён и терминов канала — в `channel/profile.md`.

## Качество транскрипта

- ASR на русском регулярно путает похожие по звучанию слова, неверно склеивает числа
  ("тридцать пять" может распознаться как "тридцать" + "пять" отдельными словами) и иногда
  галлюцинирует служебные фразы на затухающей тишине в хвосте файла (титры/подписи
  переводчиков). `transcribe.py` уже фильтрует известные маркеры такой галлюцинации
  (`редактор субтитров`, `corrector`, `amara.org` и т.п.) и обрезает транскрипт на первом
  таком сегменте — если увидишь подозрительно оборванный конец транскрипта близко к концу
  файла, это, скорее всего, оно, а не баг.
- Не пытаться исправлять смысловые ошибки распознавания вручную "на глаз" по одному слову —
  если фраза выглядит бессмысленной, свериться с реальным временем в видео (`ffmpeg -ss ...`
  вырезать секунду-две и посмотреть/послушать) прежде чем полагаться на неё как на цитату.
- Транскрипт — это ЧТО сказано и КОГДА, дословно. Никогда не перефразировать реплики
  спикера при их использовании ниже по пайплайну (shorts-script-editor режет и переставляет,
  но не меняет слова).

## Выход

`transcripts/<clip_id>.json` + `.txt`. `source.transcript_path` в edit plan проставляется
следующей стадией ([[viral-moment-finder]]), которая первая начинает реально читать текст.
