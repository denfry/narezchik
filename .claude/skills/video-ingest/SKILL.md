# video-ingest

Технический вход в пайплайн. Ничего не решает редакторски — только устанавливает факты об
исходнике, на которые опираются все последующие шаги (транскрипция, выбор моментов, монтаж).

## Когда использовать

В самом начале работы над новым видео из `input/`, прежде чем что-либо транскрибировать
или резать. Также если пользователь просит "проверь исходник" / "что за файл" / упоминает
проблемы с качеством видео (не тот аспект, странный звук, несколько дорожек).

## Что делать

1. Убедиться, что видео лежит в `input/` (никогда не читать/писать в `input/` иначе, чем
   на чтение — исходники неприкосновенны).
2. Запустить `python scripts/pipeline/probe_video.py input/<файл> --json-out temp/<clip_id>_probe.json`.
   Скрипт делает всю техническую работу (ffprobe + ffmpeg ebur128 для loudness) и печатает
   JSON с полями: `path, duration_sec, fps, width, height, orientation, video_codec,
   audio_codec, audio_channels, audio_tracks, loudness_lufs, bit_rate, file_size_bytes`.
3. Придумать `clip_id` — короткий стабильный слаг на латинице от содержания видео
   (напр. `podcast_ep12`), если пользователь не задал его явно. Этот id будет
   именем файлов во всех стадиях (`edit-plans/<clip_id>.json`, `transcripts/<clip_id>.json`,
   `output/<clip_id>_short01.mp4` и т.д. — у одного длинного исходника обычно много
   отдельных edit plan'ов, по одному на каждый найденный шортс, с суффиксом `_shortNN`).
4. Создать `edit-plans/<clip_id>.json`, заполнив только `project` и `source` по схеме
   `schemas/edit-plan.schema.json`. Остальные секции (`clip`, `speech_edits`,
   `subtitle_events`, `render_settings` и т.д.) на этом шаге пустые/дефолтные —
   их заполняют следующие стадии. `project.stage = "ingested"` (момент ещё не выбран;
   `"moment_selected"` выставит viral-moment-finder уже в планах `_shortNN`).
5. Прогнать `python scripts/pipeline/validate_edit_plan.py edit-plans/<clip_id>.json` — на
   этой стадии он выдаст ожидаемые warning'и про пустые speech_edits, это нормально;
   реальные ошибки (битые пути, некорректные числа) — нет.

## На что обратить внимание и сообщить пользователю

- **Ориентация исходника.** Если `orientation` уже `portrait` (кто-то снял вертикально) —
  это меняет стратегию кропа в visual-director (не нужно вырезать 9:16 из широкого кадра).
- **Несколько аудио-дорожек** (`audio_tracks > 1`) — возможно, отдельные дорожки на разных
  спикеров/микрофонах. Сообщить пользователю и уточнить, какую дорожку транскрибировать —
  не решать самостоятельно, это влияет на итоговый звук.
- **Аномальный loudness** (сильно тише/громче типичных -16…-20 LUFS) — не проблема сама по
  себе, но полезно знать заранее для sound-designer.
- **fps ниже 24 или переменный fps** — может потребовать более осторожного обращения при
  concat/punch-zoom (не re-encode'ить лишний раз без нужды).
- Если `probe_video.py` падает (битый файл, нет видео-дорожки, ffprobe не может открыть) —
  сообщить об этом прямо и не пытаться "угадать" параметры вручную.
