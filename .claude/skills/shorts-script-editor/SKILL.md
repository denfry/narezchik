# shorts-script-editor

Переводит выбранный "сырой" отрезок исходника в точный список сегментов речи
(`speech_edits`), которые пойдут в монтаж — это EDL (edit decision list), не проза.

## Когда использовать

После [[viral-moment-finder]] выбрал `clip.source_start_sec/end_sec` для конкретного
`edit-plans/<clip_id>_shortNN.json`, перед тем как за план возьмётся retention-editor.

## Что делать

1. **Черновик — скриптом, не руками:** `python scripts/pipeline/auto_cut.py
   edit-plans/<plan>.json` режет диапазон `clip.*` по паузам > 0.6 с и междометиям,
   ставит границы на сетку кадров и пишет `speech_edits`. Текст диапазона со словами —
   `python scripts/pipeline/transcript_window.py edit-plans/<plan>.json --words`
   (не читать весь транскрипт). Дальше — редакторская работа поверх черновика.
2. Удалить:
   - дословные повторы ("вот смотри, смотри, вот смотри...");
   - бессмысленные паузы длиннее естественного дыхания;
   - лишние вводные ("ну вот смотри", "короче", "как бы", если они не несут характера речи);
   - слова-паразиты ("типа", "как бы", "вот", когда они не часть авторского стиля);
   - предложения, которые не двигают мысль вперёд (чистый filler, не setup и не payoff).
3. **Не делать речь роботизированной.** Естественное дыхание, юмор, характерные обороты
   речи спикера (см. `channel/profile.md`) — сохранять. Цель — плотность, не стерильность.
   Если сомневаешься, резать ли конкретное слово-паразит — оставь, если оно часть манеры
   говорить, вырежи, если оно чисто заполняет паузу без интонационной функции.
4. Собрать в драматургию:
   - **HOOK** — первые 1-3 секунды. Если начало исходного фрагмента слабое (долгий заход,
     нет цепляющей фразы в первых словах) — **разрешено переставить порядок** внутри уже
     выбранного материала (например начать с кульминационной фразы, потом дать контекст),
     если это не искажает смысл сказанного. Никогда не выдёргивать фразу из другого места
     видео за пределами выбранного viral-moment-finder диапазона без повторного прохода
     через viral-moment-finder — так решения о выборе материала и его монтаже не мешают
     друг другу.
   - **SETUP** — минимально необходимый контекст, чтобы HOOK не повис в воздухе.
   - **DEVELOPMENT** — раскрытие мысли/истории.
   - **PAYOFF** — куда всё приходит: вывод, punchline, разрешение конфликта.
5. Каждый итоговый кусок речи — один элемент `speech_edits[]`:
   `id` (напр. `seg01`, `seg02`...), `source_start_sec`, `source_end_sec`, `role`
   (`hook`/`setup`/`development`/`payoff`/`bridge`), `transcript_text` (точная цитата —
   нужна retention-editor и QC для проверки, что смысл не искажён), `cut_reason` (кратко,
   почему обрезаны края именно здесь). Порядок элементов массива = порядок в готовом
   ролике (может отличаться от хронологии исходника, если HOOK переставлен).
6. Если стык двух сегментов рвёт слово или получается слишком резкий аудио-щелчок —
   выставить `crossfade_in_ms` (обычно 80-150ms) на втором сегменте; ffmpeg-editor
   применит мягкий audio fade на стыке. Не злоупотреблять — это для реальных аудио-
   щелчков, не общий инструмент сглаживания жёстких монтажных склеек (те делает
   jump cut осознанно, см. [[visual-director]]).

## Проверка перед сдачей

- Прочитать получившуюся последовательность `transcript_text` подряд как единый текст —
  она должна читаться как связная мысль, без выпавших смысловых связок.
- Ни одно слово не приписано спикеру — весь текст `transcript_text` дословно взят из
  транскрипта.
- Длительность результата (сумма `source_end_sec - source_start_sec` по всем сегментам)
  разумно вписывается в изначальный диапазон viral-moment-finder ± корректировка на
  вырезанный мусор — если она сильно короче исходного диапазона, это нормально (много
  вырезано), если сильно длиннее — проверить, не расползся ли монтаж за пределы
  изначально выбранного момента.

## Выход

`speech_edits[]` в edit plan, `project.stage = "script_edited"`. Дальше —
[[retention-editor]].
